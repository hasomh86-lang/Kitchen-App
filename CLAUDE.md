# Artisan Kitchen — project guide for Claude Code

Private-kitchen digital menu for a hospitality company in Saudi Arabia. Guests browse a
luxury catalog on iPads (no ordering); staff manage content and orders in a console.
Owner: Hussam. He writes in Gulf Arabic and English; reply in whichever he uses.
Arabic UI copy must be colloquial Gulf Arabic ("لغة بيضاء"), never stiff MSA.

## Hard constraints (never break)
1. **All data stays inside Saudi Arabia.** Production is one Oracle Cloud VM in Riyadh.
   Do not add any external database, storage, analytics or CDN. The only approved
   exception: *food photos* may be sent to external AI image tools for processing
   (Magnific / Gemini) — nothing else ever leaves the server.
2. **Dish photos are never altered by AI.** Upscale, cut out, center, compress only.
   No re-rendering, no changing angles, no adding/removing anything on the plate.
3. Keep the free-tier footprint: 1 OCPU / 6 GB ARM, SQLite, photos on disk.
4. Photo standard: 2000×2000, pure white background, soft contact shadow, dish ≈80 % of
   frame, WebP quality 0.90. Originals are kept (never delete an old image id on replace).

## Stack
- **API**: Hono (TypeScript) in `worker/`. One codebase, two runtimes:
  - Node (production): `server/main.ts` + `server/shims.ts` (D1-compatible shim over `node:sqlite`, KV-compatible shim over disk files). Bundled by esbuild to `release/server.mjs`.
  - Cloudflare Workers (optional/dev): `wrangler.jsonc` (D1 + KV). Not used in production.
- **Web**: React 19 + Vite + Tailwind v4, wouter, TanStack Query. `src/`. Self-hosted fonts (Cormorant Garamond / Instrument Sans / Amiri / IBM Plex Sans Arabic). Bilingual `{en, ar}` on every text field, RTL-aware.
- **Shared types**: `shared/types.ts` (roles, order status transitions, menu settings, themes).
- **DB schema**: `migrations/*.sql` (applied automatically on server boot by `server/shims.ts migrate()`). Add a new numbered file for any schema change; never edit an applied one.
- **Auth**: own email+password (PBKDF2), HttpOnly session cookie, CSRF origin check. Roles: `admin`, `sub-admin`, `butler`, `chef`.

## API map (all under `/api`, JSON, cookie auth; mutations need `Origin` header = site origin)
- `auth`: `POST /setup` (first admin), `POST /login`, `POST /logout`, `GET /me`, `POST /change-password`
- `public`: `GET /menu/:slug` (needs `x-device-token` unless menu is open), `/gate`, `/version`
- `admin`: clients, menus (`PATCH /menus/:id` with `settings`), users, `menus/:menuId/devices`, audit
- `catalog`: `GET /menus/:id/catalog`, categories CRUD + reorder, dishes CRUD + reorder, `POST /menus/:id/import` (bulk, `replace` flag)
- `orders`: `POST /menus/:id/orders`, `PATCH /orders/:id`, `POST /orders/:id/transition` (`{to}`; rules in `shared/types.ts`)
- `images`: `POST /` (multipart `file`), `POST /data-url` (base64), `POST /from-url` (admin, https only, ≤8 MB), `DELETE /:id`; public delivery `GET /img/:id` (immutable cache)
- `ai`: Gemini helpers (describe/translate/hero/angles) — only active if `GEMINI_API_KEY` set; keep it unset unless Hussam asks.

## Photo standardisation pipeline (done once by hand on 2026-10-24; to be built into the admin)
Per photo: Magnific **Precision** upscale 4x (`mode: ultra-sublime`, sharpness 8, grain 4 — zero creativity)
→ Magnific background removal (transparent PNG) → composite: trim alpha bbox, scale so the longer
side = 80 % of 2000, center (+1 % down), soft shadow (blurred silhouette, α 0.22, blur ≈ 24 px,
offset 2 % of height), white fill → WebP 0.90 → upload via `/api/images/data-url` → `PATCH /api/catalog/dishes/:id {image}`.
Reference implementation of the composite step is the browser-canvas code in the project doc
"artisan-kitchen-v2-architecture" (Claude project "Food Menu"); port it to `worker/routes/images.ts`
(server-side, e.g. with `sharp` — ARM build is fine) when building the admin button.
Status: all 80 visible dishes done (78 unique photos). 71 hidden dishes + 5 category hero images not done.
Magnific cost ≈ 360–450 credits/photo; account balance was ≈1.9k after the run — Hussam tops up before batch jobs.
